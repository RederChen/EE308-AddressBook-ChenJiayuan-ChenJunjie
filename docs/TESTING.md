# 测试与验收（V1.3.0）

## 已实际验证

在 Windows、Python 3.13 环境中，安装 `requirements.txt` 后执行 `python -m pytest -q`，结果 **66 passed**。分布：API 错误 8、联系人 15、Excel 12、前端契约 7、导入策略 12、界面/配置 3、联系方式标签 9。`node --check addressbook/static/app.js` 通过。

真实 Chrome 浏览器冒烟（临时 SQLite 数据库）通过：创建含“工作”标签的联系人、收藏、跳过/覆盖两种预览、切换模式后预览失效、覆盖导入、筛选导出，以及 390px 窄屏无横向溢出。测试没有在 Render 公网环境执行，不能据此声称已部署。

## 提交前人工复核

1. 在干净环境安装依赖，运行全部测试；检查 `/api/health` 的版本为 `1.3.0`。
2. `python seed_demo.py`、`python app.py`，访问首页并检查六位虚构联系人。
3. 新建一人两种联系方式及独立标签，编辑其中一条，刷新后确认标签仍在。
4. 收藏、搜索、排序、删除、撤销、回收站恢复和批量操作各试一次。
5. 导出 `.xlsx`，确认主表及“联系方式标签”工作表；导入前分别选择跳过与覆盖，观察预览数量，切换模式后应要求重新预览。
6. 在实际 Render URL 再做上述关键流程；若使用免费套餐，测试数据会在休眠或重部署后重置。

## 已知限制与检查口径

- Excel 只支持 `.xlsx`；单文件 ≤5 MiB、单次 ≤2000 行、批量操作 ≤500 个 ID。
- “导出当前列表”在回收站视图会导出**当前回收站记录**，在其他视图则不会包含回收站记录；请勿误认为它永远只导出未删除联系人。
- 预览和正式导入之间若数据库被其他访问者修改，结果可能变化。预览是提示，不是锁定数据库的承诺。
- 浏览器冒烟只覆盖典型流程；自动测试不等于所有设备与 Render 配置均已验证。
