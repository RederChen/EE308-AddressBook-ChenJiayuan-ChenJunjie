# 作业要求追踪矩阵

> 来源：[Extreme Programming (Address Book Application)](https://bbs.csdn.net/topics/620593436)  
> 截止时间：2026 年 11 月 17 日 23:59（北京时间）

## 1. 功能与评分要求

| 要求 | 分值 | 实现位置 | 验证方式 | 状态 |
|---|---:|---|---|---|
| 收藏/书签联系人，醒目标识且便于访问 | 25 | 星标切换、仅看收藏筛选、`favorite` 字段及索引 | 收藏接口与筛选自动化测试；界面截图 | 本地实现 |
| 单个联系人支持手机、邮箱、社交账号、地址等多种信息 | 10 | `contact_methods` 独立表，允许同类型多条记录 | CRUD 与多联系方式测试；编辑界面 | 本地实现 |
| Excel 导出，每个联系人一行，每类信息有明确列名 | 25 | `addressbook/excel.py`、导出接口 | 工作簿表头、行数及多值单元格测试 | 本地实现 |
| 读取兼容格式 Excel 并导入联系人 | 25 | 导入接口、字段校验、重复姓名策略与结果反馈 | 有效/无效/重复/多值导入测试 | 本地实现 |
| 可用界面且程序运行正确 | 页面 10 | 响应式单页界面、搜索、筛选、详情、编辑、导入导出 | 自动化测试与人工演示 | 本地实现 |
| 可选公有云部署 | +15 | 提供 Docker 运行方式与部署说明 | 必须提供非 localhost 公网链接 | 待团队实际部署 |

## 2. 工程与协作要求

| 要求 | 交付物/操作 | 状态 |
|---|---|---|
| 编码前规划模块边界和职责 | `docs/design.md`、`docs/collaboration.md` | 已提供规划模板，团队须确认真实分工 |
| Fork 指定仓库并建立 GitHub 团队仓库 | GitHub 外部操作 | 待提供教师仓库与团队仓库地址 |
| 约定代码规范与 Git 工作流 | `docs/code-standards.md` | 已提供 |
| 两位成员均有实质编码贡献 | 两人分别提交可审查的代码提交 | 待两位成员真实完成，不可由文档代替 |
| 仓库至少三次提交并统计每人提交数 | GitHub commit history 截图与统计 | 待真实 GitHub 仓库证据 |
| 上传源码和文档，可复现构建运行 | 根目录源码、`requirements.txt`、`README.md` | 本地完成 |
| Release 一个项目版本并发起 Pull Request | GitHub Release 与 PR | 待团队仓库操作 |

## 3. 每位成员的个人 CSDN 博客

| 必备内容 | 对应材料 | 状态 |
|---|---|---|
| 指定格式的信息表、Markdown 目录 | `docs/blog.md` | 已生成，个人/团队链接待填 |
| GitHub、代码规范、应用（可选）等链接 | 博客“项目链接” | 真实 URL 待填 |
| 提交历史截图及每人提交数 | `evidence/` 与博客对应章节 | 待真实仓库证据 |
| 功能实现思路和方法 | `docs/design.md`、博客对应章节 | 已生成 |
| 程序截图与完整运行演示视频 | `evidence/screenshots/`、`evidence/video/` | 本地证据按实际生成情况登记 |
| 清晰分工 | `docs/collaboration.md`、博客 | 待填真实姓名与职责 |
| 贡献比例，总和 100% | 协作文档与博客 | 待团队真实协商 |
| 每人遇到的问题与解决方案 | 协作文档与博客 | 待成员根据真实经历补充 |
| 每人一张 PSP 表 | `docs/psp.md`、博客 | 已提供两表，真实工时待填 |
| 发布个人博客并提交自己的链接 | CSDN 与课程提交渠道 | 待每位成员本人完成 |

## 4. 验收边界

本地代码、测试和通用文档可以预先完成；GitHub 提交作者、团队分工、贡献比例、PSP 实际工时、公开发布链接和云端地址必须来自真实操作，不能用虚构信息替代。博客中所有 `待填写` 项在提交前必须清零。
